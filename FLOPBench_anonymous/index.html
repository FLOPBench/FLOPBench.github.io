gpuFLOPBench

A benchmark and analysis site for studying whether off-the-shelf LLMs can provide Roofline-oriented GPU triage by predicting profiler-derived Roofline Arithmetic Intensity (RAI) for the 254 sampled paper kernels.

Read motivation Explore performance Rank predictions

Why this project exists

  • Motivation. Profiler-driven GPU optimization breaks down when target hardware is unavailable, rationed, or too costly for early-stage triage.
  • Signal. Roofline Arithmetic Intensity (RAI) gives an interpretable quantity for deciding whether effort should focus on memory traffic or computation.
  • Goal. The site exposes the corpus used to test whether prompting alone is enough for modern LLMs to approximate that signal across multiple GPUs.
Research framing

Motivation, key question, and the claims reviewers can inspect.

The paper asks whether off-the-shelf LLMs can predict a kernel's Roofline Arithmetic Intensity (RAI) well enough to support early GPU-kernel triage before direct hardware profiling is available. This page links those claims to exact profiled kernels, LLM predictions, prompts, responses, and error metrics.

motivation

Profiler-driven optimization does not scale to every iteration.

Typical LLM-based GPU optimization loops depend on repeated execution and profiling of candidate variants. That coupling makes optimization quality dependent on accelerator availability, which is often the scarcest resource during early kernel triage.

key question

Can prompting alone recover a useful Roofline Arithmetic Intensity signal?

The central question is whether off-the-shelf state-of-the-art LLMs, without task-specific training or fine-tuning, can act as GPU Roofline triage tools by predicting a kernel's Roofline Arithmetic Intensity (RAI).

findings

Three paper claims are directly inspectable.

  • SASS helps. Post-compilation artifacts substantially improve FP16 RAI estimates and compute/bandwidth-bound classifications for stronger models.
  • Budget matters. Premium models are strongest overall, but a cheaper model remains surprisingly competitive when only source code is available.
  • Reliability varies. Larger-cache GPUs are easier than smaller-cache GPUs, and errors concentrate around division, transcendental math, reusable subexpressions, and loop-invariant floating-point work.
contributions

What the study contributes.

  • Zero-training triage. It shows that prompted, off-the-shelf LLMs can estimate RAI well enough to support early Roofline triage across multiple GPU architectures.
  • Compiler-realized behavior. It quantifies when adding SASS improves prediction quality over source-only reasoning.
  • Reliability map. It compares inexpensive and premium models across CUDA/OpenMP, GPU cache regimes, and source features that systematically raise prediction error.
  • Benchmark release. It publishes kernels, compilation and execution context, post-compilation artifacts, and profiler-derived ground truth for hardware-free RAI prediction.
Benchmark structure

One benchmark, multiple layers of visibility.

gpuFLOPBench is not just a single score. It exposes the benchmark from the inventory level down to exact kernel rows so that category coverage, roofline behavior, and source-level detail stay visible at the same time.
